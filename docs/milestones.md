# マイルストーン

現状は [inventory_2026-10-27.md](inventory_2026-10-27.md) を参照。

## 進め方のルール

- マイルストーンは「ユーザーができること」で区切る。レイヤー（API だけ・画面だけ）では区切らない。
- **完了の定義（全マイルストーン共通）**: 次の4つがそろって、実際に動くこと。
  1. API（RSpec 通過）
  2. Web 画面（実機で操作して確認）
  3. 仕様書（OpenAPI / `apps/api/docs/interfaces/rest`）の更新
  4. CI が緑
- 同時に進めるのは1つだけ。完了するまで次に着手しない。途中で思いついた作業は該当マイルストーンの末尾か「後回し」に書く。

## M5 外から使える

**到達点**: 自分のスマホやブラウザから、本番環境で使える。

**準備**: 本番で実際に使い始める前に、未払いのカードの開始残高を登録できるようにする（M2 のカード払いと M3 の残高に関わるため。開始資産登録の負債版）。

- [x] 開始負債の登録（DB 関数 `create_opening_liability_balance_journal`。借方: 元入金、貸方: カード。引き落とし仕訳は、指定した引き落とし日で自動的に作る）
- [x] 開始負債の API（`POST /liability-opening-journals`）と画面（開始日・カード・未払いの金額・引き落とし日）、トップページの導線

- [x] 費用科目のダミー根（root）を廃止し、親のない科目をトップレベルにする（本番の seed に入れる前に整理する）

**方針**: 最初は単一 VPS に Kamal で置き、いずれ PaaS に移す。移しやすいよう、特定の置き場所に依存させない（設定は環境変数、DB 接続は `DATABASE_URL` またはホスト指定、イメージは Kamal 専用にしない）。Cookie は production で secure にしているので、HTTPS（ドメイン）が必須。

**本番のデータ**: 空の DB から始め、開発 DB のデータは移さない。seed（共通の費用科目・資本科目、祝日、ユーザーと各口座・カード）を入れたあと、開始資産・開始負債を画面から登録する。

- [x] 本番用の Dockerfile（`apps/api/Dockerfile`、`apps/web/Dockerfile`）を作り、イメージのビルドと起動を確認する（本番は DB を 1 つにし、Solid Queue / Cache / Cable の DB を持たない）
- [x] 本番のシークレット管理（`SECRET_KEY_BASE`、`JWT_SECRET_KEY` を環境変数で渡す。`RAILS_MASTER_KEY` は使わない）と、初期データ（seed）の入れ方を手順書にする（[deployment.md](deployment.md)。置き場所ごとの設定は、準備が済んでから追記する）
- [ ] Kamal の設定（`deploy.yml` を実値にする。Rails は外部に公開せず Next.js からだけ呼ぶ）と、VPS・ドメイン・イメージ置き場の準備
- [ ] PostgreSQL の運用（VPS 上のコンテナ）と、日次バックアップ（別の場所へ保管）・復元の確認
- [ ] 本番で M1〜M4 の操作を一通り行う（スマホから確認）

**完了条件**: 本番環境で M1〜M4 の操作が一通りできる。
