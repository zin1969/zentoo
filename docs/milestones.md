# マイルストーン

現状は [inventory_2026-10-27.md](inventory_2026-10-27.md) を参照。

## 進め方のルール

- マイルストーンは「ユーザーができること」で区切る。レイヤー（API だけ・画面だけ）では区切らない。
- **完了の定義（全マイルストーン共通）**: 次の4つがそろって、実際に動くこと。
  1. API（RSpec 通過）
  2. Web 画面（実機で操作して確認）
  3. 仕様書（OpenAPI / `apps/api/docs/interfaces/rest`）の更新
  4. CI が緑
- 同時に進めるのは1つだけ。完了するまで次に着手しない。途中で思いついた作業は該当マイルストーンの末尾か「後回し」に書く。

## M6 登録した仕訳を修正・削除できる

**到達点**: 登録を間違えたとき、画面から削除して登録し直すか、お買い物の仕訳ならその場で修正できる。

**方針**:
- 削除は全種類の仕訳（お買い物・開始資産・開始負債・預け入れ）でできる。DB から完全に消す（取消仕訳は作らない）。個人利用で、毎日のバックアップがあるため。
- 修正はお買い物の仕訳（借方がすべて費用）だけ。登録と同じフォームで直す。それ以外は削除して登録し直す。修正は DB の中で「削除して登録し直す」を 1 回の処理で行うので、登録と同じ確認が効き、仕訳の ID は変わる。
- カード払いの引き落とし仕訳は自動で作られたものなので、単独では修正・削除できない。元の仕訳を消すと一緒に消え、元の仕訳を直すと作り直される。引き落とし日を過ぎていても同じ。
- 他人の仕訳は、存在しない仕訳と同じ扱い（404）。

## M7 カードの引き落とし日を変更できる

**到達点**: 自動で作られた引き落とし仕訳の日付を、カードの明細の引き落とし日に合わせて直せる。締め日の近くで買うと、カード会社の計上日の都合で引き落としが翌月になることがあるため。

**方針**:
- 変えられるのは、引き落とし仕訳の日付だけ。金額・科目・口座は変えない。
- 変更後の日付は、元の仕訳の日付（買った日。開始負債なら開始日）より前にはできない。それ以外は自由で、土日・祝日でも営業日にずらさない（明細の日付をそのまま入れる）。
- 手で変えたことを `direct_debit_journals` に記録する。元のお買い物を修正したとき、同じカード 1 枚での支払いのままで、修正後の買った日より前にならなければ、変えた日を引き継ぐ。それ以外は自動の計算に戻す。
- 他人の仕訳は、存在しない仕訳と同じ扱い（404）。

- [x] 手で変えた印の列と、引き落とし日を変える DB 関数（`update_direct_debit_date`）

- [x] 引き落とし日の変更の API（`PUT /direct-debit-journals/{id}`）と、仕訳一覧の引き落とし仕訳からの変更（日付の入力）。手で変えた引き落とし仕訳には印を出す
- [x] 仕様書（OpenAPI / `apps/api/docs/interfaces/rest`）の更新

## M8 口座・カード・費用科目を画面から管理できる

**到達点**: 口座（現金・預金・電子マネー）、クレジットカード、費用科目を、seed やコンソールを使わずに画面から追加・変更・削除できる。

**方針**:
- 口座とカードはユーザーごと。費用科目は共通科目（`user_id IS NULL`）で、親子の 2 階層（親は親のない科目だけ）。
- クレジットカードは、負債科目（`liability_accounts`）と引き落とし設定（`credit_cards`。締め日・支払日・引き落とし口座）を一緒に登録・変更する。引き落とし口座は預金口座だけ。
- 仕訳で使っている科目は、名前（とカードの締め日・支払日・引き落とし口座）だけ変えられる。削除と種別の変更は、仕訳で使っていない科目だけ。仕訳の明細は科目を ID で参照していて外部キーがないため、消すと一覧に「不明な科目」が出るのを防ぐ。
- 次の場合も削除できない: カードの引き落とし口座になっている預金口座、子科目がある費用科目。
- カードの締め日・支払日・引き落とし口座を変えても、登録済みの引き落とし仕訳は変えない（これから登録する分から使う）。
- 同じ名前の科目は作れない（口座・カードは本人の中で、費用科目は同じ親の中で）。
- 他人の口座・カードは、存在しないものと同じ扱い（404）。

- [x] 口座の追加・変更・削除の API と画面（管理画面 `/accounts`）
- [x] クレジットカードの一覧・追加・変更・削除の API と画面（引き落とし設定も一緒に）
- [x] 費用科目の追加・変更・削除の API と画面

## M9 預金口座の通帳を見られる（引き落とし予定つき）

**到達点**: 預金口座ごとに、銀行の通帳のような出入金の一覧（日付・摘要・出金・入金・残高）を見られる。未来の引き落とし予定も並び、残高が足りなくなる日が分かる。

**方針**:
- 対象は預金口座だけ（カードの引き落としがあるのは預金口座だけのため）。
- 1 行は 1 つの仕訳。ただしカードの引き落としは、同じ日・同じカードの分を 1 行にまとめて合計を出す（本物の通帳と同じ）。行を開くと、元のお買い物の内訳（日付・店舗・金額）が見られる。
- 残高は、期間の初日の前日までの残高（繰越）から、1 行ずつ積み上げる。計算は DB 関数（`get_bank_account_ledger`）で行う。
- 今日（日本時間）より後の行は「予定」と分かるようにし、残高がマイナスになる行には不足の印を出す。
- 既定の期間は、先月の初めから、その口座の最後の予定日まで（最後の予定が今月より前なら今月末まで）。開いたあとで期間を変えられる。
- 他人の口座、預金ではない口座は、存在しない口座と同じ扱い（404）。

- [x] 通帳の行を作る DB 関数（`get_bank_account_ledger`。繰越、カードの引き落としのまとめ、残高の積み上げ）
- [x] 通帳の API（`GET /bank-account-ledgers/{id}`。期間、繰越、行、カードの行の内訳、予定かどうか）
- [x] 通帳の画面（口座の選択、期間、予定と不足の印、カードの行の内訳）と、トップページの導線
- [x] 仕様書（OpenAPI / `apps/api/docs/interfaces/rest`）の更新
- [x] 本番にデプロイし、スマホで確認する（2026-11-21）

**完了条件**: 本番で、預金口座の通帳を開くと、実際の残高の動きと引き落とし予定が日付順に並び、残高が足りなくなる予定が分かる。

## M10 収入を登録して、月ごとの収支が見える

**到達点**: 給料などの収入を登録・修正・削除でき、残高と通帳に入金として反映される。月次の画面で、月ごとの収入と収支（収入 − 支出）が見える。

**方針**:
- 収益科目（`revenue_accounts`）を新しく作る。費用科目と同じく全ユーザー共通（`user_id IS NULL`）で、親子の 2 階層。最初の科目は seed で「給与」「賞与」「雑収入」を入れる。管理画面（`/accounts`）から追加・変更・削除でき、ルールは費用科目と同じ（使っている科目は名前だけ変えられる、子科目のある科目は削除できない）。費用科目の管理の仕組みを共通化して使う。
- 収入の仕訳は、借方: 入金先の口座、貸方: 収益科目。入金先は本人の口座ならどれでもよい（預金・現金・電子マネー）。1 回の登録は、収益科目 1 つ・入金先 1 つ・金額 1 つ。
- 項目は、日付・入金先・収益科目・金額・摘要（支払元など。任意）。摘要は仕訳の店舗名に入れ、空なら収益科目の名前を入れる（通帳の摘要に出るため）。
- 修正は、お買い物と同じく「削除して登録し直す」を DB の中で 1 回の処理で行う（仕訳の ID は変わる）。仕訳一覧の収入の仕訳に「修正」を出す。削除は既存の仕訳の削除をそのまま使う。
- 月次の画面に、収益科目ごとの収入と、収入の合計・支出の合計・収支を足す。
- 他人の口座・科目は、存在しないものと同じ扱い（404）。

- [x] 収益科目のテーブル・seed・一覧 API と、管理画面の欄（費用科目の管理を共通化）

## M11 口座から口座へお金を動かせる（引き出し・振替・チャージ）

**到達点**: ATM での引き出し、口座間の振替、電子マネーへのチャージ（現金・預金・クレジットカードから）を 1 つの「振替」画面で登録・修正・削除でき、残高と通帳に反映される。

**方針**:
- 振替の仕訳は、借方: 入れる先の口座、貸方: 出す元（口座、またはクレジットカード）。出す元と入れる先は本人のもので、同じ口座にはできない。
- クレジットカードから入れられるのは電子マネーだけ（チャージ）。カードからのチャージは、お買い物のカード払いと同じく、引き落とし仕訳を自動で作る（通帳に引き落とし予定として出る）。
- 摘要は任意。空なら組み合わせから自動で入れる（預金 → 現金は「引き出し」、現金 → 預金は「預入」、電子マネーへは「チャージ」、それ以外は「振替」）。
- 手数料は扱わない（お買い物登録で費用として別に登録する）。
- 修正は、お買い物・収入と同じく「削除して登録し直す」を DB の中で 1 回の処理で行う（仕訳の ID は変わる）。振替の仕訳は「借方が口座 1 つ、貸方が口座かクレジットカード 1 つ」で見分ける（登録済みの「現金の預け入れ」も振替として修正できる）。カードからのチャージを修正すると、引き落とし仕訳は作り直し、引き落とし日は自動の計算に戻す（M7 の引き継ぎはお買い物だけ）。
- 「現金の預け入れ」は振替にまとめる。トップページの導線を「振替」に置き換え、Web の預け入れ画面は削除する（Rails の `POST /cash-deposit-journals` は残す）。
- 他人の口座・カードは、存在しないものと同じ扱い（404）。

**方針**:
- お買い物登録に「税込 / 税抜（外税）」の切り替えを置く。税抜では、明細ごとに税率（10% / 8% / その他の数値）を選ぶ。

## M13 毎月の決まった支払いを、確かめてから登録できる

- 対象は支出（お買い物と同じ形: 借方が費用、貸方が支払い方法）と収入（収入登録と同じ形）。登録はそれぞれ今までの登録の処理を使う。カード払いなら、引き落とし仕訳も今までどおり自動で作られる。振替（積立・オートチャージ）は「後回し」。

- 日は 1〜31 か月末。月に無い日（2 月 30 日など）は月末にする。土日・祝日でも営業日にずらさない。
- 開始日は必須、終了日は任意。終了日を過ぎた回は出さない。

## M18 現物株を銘柄ごとに管理できる

**到達点**: 現物株を銘柄ごとに、株数と取得額で管理できる。今持っている株を、株数と平均取得単価で開始残高として登録し、そのあとの売買・配当を記録できる。

**方針**:
- 銘柄ごとに、種別「投資」の資産の口座を 1 つ作る（例: 「トヨタ 7203」）。取得額は口座の残高。
- 仕訳の明細に株数を持たせる。銘柄の株数は株数の合計。
- 開始残高: 借方 銘柄 / 貸方 元入金。金額 = 株数 × 平均取得単価。今の開始資産の登録を、株数も入れられるように広げる。
- 買う: 借方 銘柄（株数 +n）/ 貸方 証券口座（預り金）。手数料は取得額に含める。
- 売る: 借方 預り金（受け取った額）/ 貸方 銘柄（株数 −n、金額 = 平均取得単価 × n）。差額は売却益（収益）か売却損（費用）。平均取得単価は移動平均（それまでの取得額 ÷ 株数）。
- 配当: 借方 預り金 / 貸方 配当金（収益）。収入登録で、源泉徴収のあとの手取りの額で記録する。
- 売買は借方・貸方が 1 行ずつの振替に収まらないので、売買の登録画面を別に作る。
- DB を変える（明細の株数、売却益・売却損・配当金の科目）。

- [ ] DB・API: 明細の株数、銘柄ごとの株数・取得額・平均取得単価の取得、売買の登録、開始残高に株数
- [ ] Web: 株の開始残高・売買の登録画面、銘柄ごとの株数・取得額の一覧
- [ ] 仕様書（OpenAPI / `apps/api/docs/interfaces/rest`）の更新
- [ ] 本番にデプロイし、スマホで確認する（DB を変えるので、先に手動でバックアップ）

**完了条件**: 本番で、今持っている株を株数と平均取得単価で登録し、買い・売り（売却損益）・配当を記録して、銘柄ごとの株数と取得額が合っている。
